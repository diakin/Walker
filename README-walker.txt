WALKER - игра про шагающих роботов на движке Quake III Arena (GPL)
=================================================================

Отдельная игра со своими данными: файлы Quake III (baseq3, pak0.pk3) не нужны.
Цель - аналог War Robots, который работает на старом железе и старых ОС (Windows XP/7, OpenGL 1.2).

Сейчас есть:
- робот walker (вид от третьего лица, без прыжков, автопушка с бесконечным боезапасом);
- карта wk_islands "Islands": острова с мшистыми руинами в мелкой воде, скалы по краям,
  башня с кольцевой платформой, стартовая ферма с ракетой, вертолётные площадки,
  платформы на опорах, маяки A-E (пока только как ориентиры, захвата нет);
- боты: 8 пилотов (Anvil, Bastion, Cinder, Drake, Ember, Flint, Granite, Hornet) с разным
  характером, три окраски робота (стандартная, desert, urban);
- свои шрифты, меню, прицелы, HUD, эффекты и синтезированные звуки.

- пилоты (аккаунты), три робота с характеристиками и развитием (раздел «Пилоты и роботы»).


Сборка и запуск
---------------

Нужен 32-битный MinGW (gcc, windres, mingw32-make). 64-битный компилятор не подходит:
ни движок, ни компилятор lcc не рассчитаны на 64 бита.

1. Сборка (из папки code):
     mingw32-make -f Makefile.mingw
   Цели: all (по умолчанию) = engine + dll + qvm; engine - только Walker.exe;
   dll - игровой код сервера и cgame в машинных кодах (basewalker/qagamex86.dll,
   cgamex86.dll); qvm - игровые модули байт-кодом; clean - удалить результаты сборки.

   Порядок внутри all:
   - engine: code/*.c -> code/build-mingw/*.o -> walker/dist/Walker.exe
   - qvm (code/Makefile.qvm): сначала инструменты из исходников репозитория
     (lcc/: lburg, rcc, cpp; q3asm/) в code/build-qvm-tools, затем
     code/game, code/cgame, code/q3_ui -> walker/dist/basewalker/vm/qagame.qvm, cgame.qvm, ui.qvm
   - dll: code/game, code/cgame -> code/build-dll-game, build-dll-cgame -> basewalker/qagamex86.dll,
     cgamex86.dll. С 26.11.2026 игра берёт их вместо qvm (com_nativeGame 1, по умолчанию;
     0 - снова qvm). QVM в этой сборке шли в интерпретаторе (у MinGW нет генератора кода
     vm_x86.c): ИИ ботов, игра сервера и cgame занимали около половины кадра боя на FX-6300.
     Если dll нет, берётся qvm. Меню (ui) осталось qvm. Чистота сервера (sv_pure) dll не
     запрещает: они идут с игрой, а не с модом.

2. Готовая папка игры - walker/dist:
     Walker.exe
     basewalker/pak0.pk3        (данные, в репозитории)
     basewalker/wk_islands.pk3  (карта, в репозитории)
     basewalker/vm/*.qvm        (только что собранные модули)
     basewalker/qagamex86.dll, cgamex86.dll  (игровой код в машинных кодах)
   Файлы из папки basewalker имеют приоритет над теми же файлами внутри pk3, поэтому
   собранные QVM заменяют старые копии из pak0.pk3.

3. Запуск (рабочая папка - walker/dist, движок ищет basewalker в текущей папке):
     Walker.exe +set bot_minplayers 6 +map wk_islands   (6 участников: вы и боты)
   Или из меню: SINGLE PLAYER (бой с ботами) или MULTIPLAYER -> START SERVER -> Islands.
   В оконном режиме окно вместе с рамкой и заголовком помещается в рабочую область
   рабочего стола (без панели задач): если режим больше, картинка уменьшается с теми же
   пропорциями (в консоли: "window ... does not fit the desktop, using ...").

После правки любого .h пересобирается всё (так проще и надёжнее, чем отслеживать зависимости).
pk3 с данными пересобираются отдельно (Python, см. "Пересборка данных"), для обычной
работы с кодом это не нужно.

Движок теперь ищет данные в папке basewalker (BASEGAME в code/qcommon/qcommon.h) и не
требует CD-ключа и файлов Quake III.


Боты
----

SINGLE PLAYER открывает экран настройки боя: карта, затем список ботов и их уровень
(Bot Skill), кнопка FIGHT. По умолчанию bot_minplayers 6: если игроков меньше шести,
сервер сам добавляет ботов (по одному раз в 10 секунд). Отключить: bot_minplayers 0.

В игре: Esc -> BOTS - список всех ботов, щелчок по имени добавляет бота в бой
(с уровнем из строки "Skill of new bots") или убирает его.

Команды консоли:
  addbot Anvil 3        добавить бота (уровень 1-5)
  kick Anvil            убрать бота
  team spectator        стать зрителем; follow Anvil - смотреть за ботом

Ботам нечего подбирать (на карте нет предметов), поэтому они ходят между маяками A-E
и точками появления и вступают в бой с теми, кого видят.


Управление
----------

W A S D - ходьба, мышь - поворот корпуса и прицел, ЛКМ - огонь, ПКМ - приближение,
TAB - следующая цель в рамку, Q - счёт, ~ - консоль, ESC - меню, F12 - снимок экрана (basewalker/screenshots).


Замер производительности
------------------------

WalkerBench.exe (копия Walker.exe; движок узнаёт режим по слову "bench" в имени файла):
запуск без всяких действий. Свои настройки игрока (q3config.cfg, autoexec.cfg, balance.cfg)
не читаются и не перезаписываются - всё по умолчанию, окно 1024x768, com_maxfps 250
(basewalker/benchmode.cfg в pak0). Запускается командный бой на Острове без лимитов,
игрок - зритель. Сначала замер без ботов, затем боты добавляются по два (команды по
очереди, до 5 x 5) и каждый раз 6 с замера: таблица "bots entering the battle" показывает,
сколько стоит робот в бою. Потом шаги замера, benchmark.log открывается, игра закрывается.
Другая карта (с 27.11.2026): WalkerBench.exe +set bench_map wk_bigbeacons (по умолчанию
wk_islands; карту запускает движок после benchmode.cfg, qcommon/common.c). Несколько карт подряд:
список через пробел (+set bench_map "wk_islands wk_bigbeacons") или all — wk_islands, wk_beacons,
wk_bigbeacons. На каждой карте весь замер (боты входят по двое, затем все шаги), перед следующей
боты выгоняются (kick allbots); отчёты идут друг за другом в benchmark.log, в конце сводка: шаги
base (бой со всеми ботами) и frozen каждой карты. Все три карты — около 13 минут.
Свои настройки (с 27.11.2026): WalkerBench.exe +set bench_mysettings 1 — тот же бой, но с
настройками игрока из q3config.cfg и autoexec.cfg: экран (r_mode, окно или полный экран),
эффекты (сглаживание, фильтр, качество текстур, тени, дымка, отражения), com_maxfps. Файл
настроек не перезаписывается. В benchmark.log строка effects и пометка "the player's own
settings"; у сглаживания — включилось ли оно на этой видеокарте (r_multisampleActive).
Окно больше рабочего стола движок уменьшает (1600x1200 на экране 1920x1200 — около 1524x1143),
настоящий размер — в строке game WxH. Ключи можно сочетать: +set bench_mysettings 1 +set
bench_map wk_bigbeacons.
Около 4 минут. Шаги, менявшие результат меньше, чем бой меняется сам (до 5 %), убраны
(26.11.2026). nothing_drawn - боты стоят и не стреляют, мир и роботы не рисуются (остаются
небо и HUD).

В бою (лучше 5 x 5 с ботами, командный бой без лимитов) в консоли: benchmark [секунд на шаг,
по умолчанию 10]. Лучше перейти в зрители (TEAM -> SPECTATOR) и оставить камеру над боем:
тогда сцена от шага к шагу меняется мало. Игра проходит шаги из basewalker/benchmark.txt
(по умолчанию из pak0; свой файл в basewalker его заменяет): каждый шаг меняет одну
настройку, 3 с ждёт и меряет; после шага настройки возвращаются. Около 5 минут на 20 шагов;
benchmark stop - прервать. Результат дописывается в basewalker/benchmark.log и в консоль:
  fps, median, 1%low - средний FPS, FPS типичного кадра (половина кадров быстрее; примерно
                     это показывает счётчик на экране - он усредняет только 4 последних кадра)
                     и FPS самого медленного 1 % кадров;
  frame            - мс на кадр; из них bots - ИИ ботов, server - остальная игра сервера,
                     client - клиент и cgame, front - сборка сцены рендером, back - вызовы
                     OpenGL и ожидание видеокарты (на время замера r_finish 1, шаг real_fps -
                     без него), остаток - звук, окно, ввод;
  cgame            - часть client, ушедшая на cgame (без сборки сцены рендером, она в front);
                     cgame - dll или qvm (строка "game code" в отчёте);
  worst            - самый долгий кадр, мс;
  lag, lag>1s      - насколько ответ сервера отставал от команд игрока (максимум, мс) и доля
                     кадров с отставанием больше секунды; "Connection Interrupted" появляется
                     при отставании примерно на 64 кадра;
  surfs            - поверхностей в кадре (столбец batches до 26.11.2026 считал их же, а не
                     вызовы отрисовки);
  shader           - сколько раз за кадр рисовался накопленный набор поверхностей одного шейдера;
  draws            - вызовов отрисовки OpenGL за кадр (glDrawElements, glBegin у теней и неба;
                     каждый слой шейдера и каждый проход света - отдельный вызов);
  ktris            - тысяч треугольников на кадр со всеми проходами;
  vs base          - разница FPS с первым шагом; base_again в конце - тот же замер, по нему
                     видно, насколько меняется сам бой; у замороженного шага - разница с
                     первым замороженным (frozen), frozen_again - его повтор;
  view             - spect: зритель, dead N %: свой робот уничтожен часть шага, frozen: шаг
                     на остановленном бое.
Слово frozen в шаге benchmark.txt: шаг идёт на бое, остановленном в один момент (время игры
не идёт, боты не думают, каждый кадр - одна и та же картинка), поэтому от замороженной базы он
отличается только своими настройками. Живой бой сам по себе гуляет на 10-15 % (два замера
26.11.2026 на одном ПК). Бой останавливается в начале первого замороженного шага и идёт
дальше на следующем живом; замороженный шаг меряется половину времени шага (не меньше 3 с)
после 1 с ожидания. Первый замороженный шаг (settle) ни с чем не сравнивается: 26.11.2026 на
одном ПК он шёл вдвое медленнее следующих (back 12.5 мс вместо 5.4), причина не найдена. Тестовый exe на время своей работы выключает композицию рабочего стола (Aero, Windows
Vista и 7; после выхода Windows включает её сама): 26.11.2026 в окне с glFinish каждый кадр
целые шаги шли ровно с частотой экрана (62.5 fps при 60 Гц), другие с той же картинкой - 120.
В сведениях о системе строка "desktop composition". Шаг с vid_restart всегда живой: перезапущенный cgame ждёт снимок от
сервера, а остановленный сервер их не шлёт.
Если бой кончился, замер останавливается и пишет то, что успел.
В начале каждой записи - сведения о системе: версия Windows и её разрядность, процессор
(ядра, потоки, частота), память (всего и свободно), схема питания, разрешение экрана,
видеоадаптеры с драйверами (поставщик, версия, дата, видеопамять), строки OpenGL и его
пределы, затем проверки: ERROR - OpenGL программный (драйвер видеокарты не установлен),
стандартный драйвер Windows вместо драйвера видеокарты; WARNING - драйвер из Центра
обновления Windows, игра на встроенной Intel при наличии NVIDIA/AMD (ноутбук), мало памяти,
схема "экономия энергии"; note - старый драйвер, мало ядер, ограничение FPS.
Те же сведения пишутся при каждом запуске в basewalker/sysinfo.txt; команда sysinfo
выводит их в консоль.
Шаги в формате "имя: cvar значение; cvar значение; vid_restart". Новое: r_noTextures 1 +
vid_restart - текстуры карты и моделей белые, остаются освещение и геометрия.

Пилоты и роботы
---------------

Пилот (аккаунт) хранится на компьютере игрока: basewalker/accounts/<ник>.acc, обычный
текстовый файл. В нём ник, уровень и опыт пилота, кредиты, очки развития и роботы ангара
(тип, уровень робота, уровень оружия, идущее улучшение и время его окончания).
При первом запуске открывается экран PILOTS: ввести ник, CREATE. Там же выбор пилота
(FLY AS), удаление (DELETE PILOT) и создание новых, до 12 пилотов. Последний выбранный
пилот запоминается (cvar ui_account) и загружается при старте, в том числе при запуске
боя сразу из командной строки (файлы .bat). В главном меню справа вверху
строка с текущим пилотом; экран PILOTS открывает пункт PILOTS главного меню (выбрать пилота:
щелчок по строке и FLY AS или второй щелчок по той же строке). Новый пилот: K7 уровня 1 и 1500 кредитов.
Для тестов (cvar ui_testHangar 1, по умолчанию) ангар любого пилота дополняется бесплатными
роботами до 5 (K7, STRIZH, MOLOT по очереди); ui_testHangar 0 отключает, выданные роботы остаются.

Роботы (code/game/bg_robots.c, таблица общая для сервера, клиента и меню):
  робот    роль         структура  броня  щит     скорость  слоты оружия              цена
  K7       основной     65 000      40    6 000   40 км/ч   2 лёгких                  3000
  STRIZH   разведчик    38 000      -    12 000   60 км/ч   1 средний + 1 лёгкий      6000
  MOLOT    танк        125 000     150    -       26 км/ч   1 тяжёлый                 9000
Броня - сколько единиц урона снимается с каждого попадания по структуре.

Оружие (урон за выстрел / выстрелов в секунду / дальность в метрах, 1 м = 5 единиц карты;
дальность не растёт с уровнем):
  OSA      лёгкое   пулемёт          290 / 8 / 450                          1200
  SHMEL    лёгкое   ракеты           2600 / 1 / 500, взрыв 60               1800
  TOPOR    среднее  автопушка        500 / 3 / 700                          2500
  ISKRA    среднее  плазма           700 / 2,5 / 600, взрыв 50              3000
  TARAN    тяжёлое  орудие           9000 / 0,5 / 750, взрыв 90             4500
  KOPYO    тяжёлое  рельсотрон       13000 / 0,3 / 1000, насквозь до 4      6000
Роли: пулемёт OSA - ближний бой и разведчики (мгновенное попадание, мелкие пули плохо
пробивают броню); ракеты SHMEL - против брони вблизи (крупный урон, но ракета летит долго);
TOPOR - средняя дистанция, против разведчиков; ISKRA - средняя дистанция, против брони;
TARAN - главный калибр танка; KOPYO - дальний бой, самая большая дальность. Чем больше
дальность, тем меньше урон в секунду в своём классе.

Время уничтожения при стандартном вооружении (секунды, все попадания, уровень 1):
  атакует \ цель      STRIZH   K7     MOLOT
  STRIZH (TOPOR+OSA)    13      21      58
  K7 (OSA+OSA)          11      18      56   с двумя SHMEL против MOLOT - 26
  MOLOT (TARAN)         11      16      28
Оружие ставится в слот своего класса. Новый робот приходит со своим набором (K7: OSA + OSA,
STRIZH: TOPOR + OSA, MOLOT: TARAN). Оружие — отдельные предметы пилота со своими уровнями:
в ангаре CHANGE WEAPON показывает оружие этого класса со склада и с других роботов (взятое
снимается с прежнего робота) и магазин; TAKE OUT оставляет слот пустым. Все стволы робота
стреляют по ЛКМ, каждый со своей скорострельностью; выстрел идёт из дульного среза слота
в точку под прицелом. Робот без оружия или с оружием на улучшении в бой не выходит.
Модели оружия: models/robotweapons/<id>.glb (make_robots.py), теги tag_weapon1.. на роботах.

Захват цели: ближайший видимый вражеский робот в пределах дальности своего оружия берётся
в красную рамку и удерживается, пока он жив, виден (до 1,5 с за укрытием) и не дальше
1,25 дальности. TAB переводит рамку на следующую цель в пределах дальности (по расстоянию).
Под рамкой - расстояние до цели в метрах и урон, нанесённый ей этим пилотом с момента
появления её робота (DMG). Над каждым своим стволом (вид сзади) - его название, дальность и урон
за выстрел с учётом уровня; серым, если цель в рамке дальше дальности этого ствола.
Старые конфиги переназначаются один раз при запуске (TAB - цель, Q - счёт, cvar cg_walkerBinds).

Баланс для тестов: SETUP -> BALANCE (из главного меню и из ESC в бою). В столбик все роботы и всё оружие:
параметр, поле NEW с новым значением и OLD (STOCK) - исходное значение из bg_robots.c.
Вверх/вниз или Tab - выбор поля, набор цифр заменяет значение (дробные - через точку
или запятую), Backspace - стереть символ, Enter или APPLY - применить, ESC и BACK тоже
применяют. ALL TO STOCK возвращает все исходные значения. Жёлтым - набрано, но не
применено, голубым - отличается от исходного. У оружия скорострельность задаётся в
выстрелах в секунду. Значения - для уровня 1, рост по уровням считается от них.
В бою свой робот и установленное оружие отмечены полосой слева и надписью справа:
YOUR ROBOT, YOURS: LEFT L2 (сторона установки и уровень).
Всё действует сразу на всех роботов в бою, включая ботов: у структуры и щита
сохраняется оставшаяся доля (было 50 % из 42 000 - станет 50 % из нового значения).
Калькулятор вверху списка: TARGET STRUCTURE (по умолчанию 70000) и NORM TIME, S
(по умолчанию 15). Под каждым оружием две вычисляемые строки:
  DPS - урон в секунду (урон x выстрелов в секунду);
  TO <структура>: время уничтожения этой структуры без щита и брони;
  FOR <норматив> s: DAMAGE - урон за выстрел, при котором время равно нормативу;
  WITH SHIELD, ARMOR - время уничтожения каждого робота 1-го уровня с его щитом и
  бронёй: щит / DPS + структура / (урон за выстрел минус броня x выстрелов в секунду).
  Восстановление щита, промахи,
  разброс и полёт снаряда не учитываются; считается один ствол.
Значения калькулятора хранятся в cvar bal_calc и в balance.cfg.
Каждое применение (и ALL TO STOCK) записывает всё в basewalker/balance.cfg: сверху
читаемая таблица (новое значение, исходное, * - изменено), ниже строки seta. Этот файл
читается при каждом запуске, так что значения не теряются, даже если удалить
q3config.cfg. Чтобы сделать подобранные значения исходными в коде, достаточно этого файла.
Хранятся в cvar bal_<id> (bal_k7, bal_osa, ...; числа через пробел в единицах таблицы:
структура, броня, щит, скорость, цена; урон, интервал в мс, дальность, взрыв, скорость
снаряда, разброс, цена), записываются в q3config.cfg и передаются сервером клиентам.

Попадание сначала снимает щит, с остатка броня снимает своё число единиц, но не больше
4/5 попадания: мелкие пули по танку проходят слабо, крупные снаряды - почти целиком. Щит
восстанавливается 12 % в секунду, если по роботу не попадали 4 секунды.
Скорость 39,6 км/ч соответствует g_speed (по умолчанию 55 ед./с), остальные пропорционально.
Масштаб: g_unitsPerMetre единиц карты в метре, по умолчанию 4.5 (27.11.2026 сначала 5 — подобран
по War Robots: робот на «78 м» у нас выглядел как робот на 73 м там при cg_fov 85; после первых боёв
4.5: цифры у цели казались маленькими, «450» стало «500»). Дальности и скорости снарядов в таблицах —
метры и м/с, в мире умножаются на g_unitsPerMetre; радиус взрыва — единицы (соразмерен роботу).
Расстояние до цели на экране — единицы / g_unitsPerMetre. Урон всего оружия умножается на
g_damageScale, по умолчанию 1.7 (27.11.2026; числа урона в таблицах и BALANCE.md — без множителя,
в ангаре и у орудий в бою — с ним).
Регулировка в бою (только на своём сервере, значения сохраняются в q3config.cfg):
  = или + на цифровой клавиатуре / - или - на цифровой — масштаб: с + число у цели растёт
      (метр короче, шаг 0.1 единицы), дальность стрельбы в метрах та же — стрелять можно, когда
      число у цели снова не больше дальности орудия;
  Shift + / Shift -  — скорость всех роботов, шаг 5 % (25..200 %, g_speed);
  Ctrl + / Ctrl -    — урон, шаг 0.1 (g_damageScale). Ctrl по умолчанию ещё и стрельба: пока
      держите Ctrl, робот стреляет.
Клавиши назначает меню при запуске (ui_atoms.c), если они свободны или заняты командами Quake
sizeup/sizedown; команда — wk_tune +1 / wk_tune -1. Новое значение коротко пишется по центру экрана.
Скорость всех роботов сразу: меню GAME OPTIONS -> Robot Speed (25..200 %, 100 % = g_speed 55) или
g_speed в консоли (сохраняется в q3config.cfg); соотношение скоростей роботов не меняется.

Развитие: 12 уровней у робота и 12 у оружия. За уровень робота +8 % структуры и щита,
+8 % брони, +1 % скорости; за уровень оружия +8 % урона и ещё +3 % урона (до 28.11.2026 эти 3 %
давали скорострельность; урон в секунду тот же, а стволы одного типа стреляют вместе).
Улучшение стоит очков развития (60 очков и 10 минут на первом уровне ... 2770 очков и
24 часа на последнем; лёгкое оружие — половина цены, среднее — две трети, тяжёлое — 85 %) и идёт в реальном времени, даже когда игра
закрыта. Робот на улучшении в бой не выходит. FINISH NOW завершает улучшение сразу за
кредиты (1 кредит за каждую оставшуюся минуту). Новые роботы покупаются за кредиты
в пустых отсеках ангара (кнопки < > листают модели). В ангаре 5 отсеков.

Награда за бой (выдаёт сервер в конце боя, меню добавляет её пилоту и пишет строкой
в главном меню):
  очки развития = 40 + 25 за сбитого + 1 за 2000 урона + 20 за маяк + 60 за победу
  кредиты       = 100 + 15 за сбитого + 10 за маяк + 150 за победу
  опыт          = 50 + 20 за сбитого + 1 за 1500 урона + 15 за маяк + 100 за победу
Уровень пилота растёт каждые 400 x уровень опыта.

В бой идут роботы ангара по порядку отсеков (кроме тех, что на улучшении). Когда сбит
последний, игрок становится зрителем и может дождаться конца боя — награда всё равно
начисляется (победа считается по команде, за которую он играл). Для проверки:
Esc -> END BATTLE (TEST) (или команда cmd endbattle) завершает бой сразу, с наградой.

Боты получают случайных роботов на уровне, близком к среднему уровню роботов игрока;
у команды противника уровень на 1 выше (g_botLevel, g_botRobots задаёт меню при старте боя).

Модели STRIZH и MOLOT собираются программно (walker/tools/make_robots.py): выпуклые тела
с фасками и цилиндры, ноги с обратной кинематикой, окраски default/red/blue, тот же набор
анимаций, что у K7; потом их запекает bake_walker.py (тени в углах, швы панелей, потёртости,
грязь) и упрощает make_lods.py. Теги слотов K7 добавлены в исходную модель
(walker/tools/add_k7_slots.py).


Пересборка данных
-----------------

Данные создаются скриптами (Linux или Windows с Python 3, numpy, scipy, Pillow):

                      слиты в прямоугольники), рельеф окрашен одной цветовой картой 2048x2048
                      на всю карту (terrain_colormap: трава, берег, мокрая полоса, дно, скала
                      смешаны плавно, граница не зависит от треугольников) плюс мелкая деталь
                      terrain_detail; крутые склоны — текстура скалы; общий крупный рисунок

                      умножается на (1 - water_mask), прибавляется water_seabed (дно, уже

В aas_walker.cfg размеры робота, скорость 110 и запрет прыжков (боты не строят маршрутов,
где нужно прыгать). Расчёт около минуты.

Компиляция карты: q3map wk_islands.map; q3map -vis wk_islands.map; q3map -light wk_islands.map
(свет считается около 5 минут). Путь к .map должен содержать папку quake*/basewalker,
по нему q3map находит текстуры и шейдеры.

Масштаб: робот высотой 56 единиц соответствует ~10 м, то есть 1 м ~ 5.6 единицы.
Карта 3584 x 2688 единиц, игровая зона ~2900 x 2050 (около 520 x 370 м).
Глубина воды не больше 20 единиц: робот идёт по дну, а не плывёт.
